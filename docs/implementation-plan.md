## 3. 测试分层与证据

- 单元测试：资源事务、人口预约、训练取消、施工与死亡清理、射程/冷却、A*切角与不可达。
- 场景测试：固定地图、种子和命令序列，检查模拟状态与关键事件；同环境不同渲染帧率下，比较相同步数的结果。
- 浏览器测试：开始游戏 → 采集 → 建造 → 训练 → 进攻 → 结算 → 重开；验证画布输入与UI隔离。
- 人工试玩：框选手感、拥堵恢复、错误提示可理解性、AI节奏。自动化不能替代可玩性判断。
- 压力测试：100单位、40建筑、300静态对象，同时移动/战斗；预热30秒、采样3分钟，记录帧耗时与模拟耗时p50/p95、寻路积压和最大活跃粒子。
- 重开泄漏检查：每次重开后记录实体、Mesh、订阅、粒子池数量；内存允许缓存波动，但不能逐次保留旧世界。需要时用堆快照核查。

测试报告必须写明设备、浏览器、代码版本、配置、执行步骤和实际结果；未执行的用例标记“未验证”，不写“通过”。

## 4. 首版完成定义

1. README提供实际可用的安装、运行、构建和测试命令。
2. 所有P0用例通过，并有可复现结果；性能目标的达成或差距如实记录。
3. 玩家能完成至少一局从采集到胜负的游戏，AI遵循相同经济规则。
4. 暂停、后台恢复、终局和重开可用。
5. 不依赖外部收费素材或运行时账号；简化特效可关闭。
6. 后续英雄、迷雾和联机需求独立排期，不阻塞首版。

## 5. 可调整的产品决策

若没有进一步指示，实施按单机AI、全图可见、无英雄、原创占位资产推进。最影响范围的调整是“首版必须含英雄”或“首版必须联机”；任何一项变化都需要重新评审模拟、交互和验收范围。
